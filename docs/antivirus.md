# Подключение антивирусов

Откройте **Антивирусы** в меню суперпользователя или перейдите в **Администрирование → Подключения антивирусов**. Выбранные подключения применяются к файлам, автоматическая проверка которых начинается после изменения конфигурации. При первом запуске включён ClamAV.

## VirusTotal

Бесплатный Public API подходит для разрешённого некоммерческого или учебного теста. Для рабочего процесса компании нужен договор, разрешающий такой сценарий. Этот адаптер использует обычный API v3. Отправленные через него файлы могут стать доступны пользователям и партнёрам VirusTotal. Подключение предназначено для файлов, которые можно публиковать. Условия и обращение с образцами описаны в [сравнении тарифов](https://docs.virustotal.com/docs/difference-public-private) и [документации загрузки](https://docs.virustotal.com/reference/files-scan).

1. Добавьте подключение типа **VirusTotal** и задайте имя, которое будет видно ИБ.
2. Введите API-ключ, подтвердите отправку файлов в общий набор данных и включите подключение.
3. В разрешённом тестовом окружении подайте новую заявку на публичный безвредный файл.
4. В карточке ИБ откройте **Результаты проверки**. Для VirusTotal видны вердикт и счётчики. Блок **Подробный отчёт** показывает результат каждого движка и ссылку на сохранённый JSON.

После отправки сохраняется ID анализа. Celery запрашивает [состояние анализа](https://docs.virustotal.com/reference/analysis) примерно раз в 30 секунд с учётом интервала планировщика и ответа `Retry-After`. Ожидание ограничено 30 минутами. После получения ID повторы запрашивают тот же отчёт. При неоднозначном результате отправки проверьте историю провайдера перед ручным повтором. Для файлов больше 32 МБ применяется [специальный адрес загрузки](https://docs.virustotal.com/reference/files-upload-url). Общий лимит приложения составляет 50 МиБ.

## Локальный антивирус

Для ClamAV используется протокол clamd из комплекта поставки. В Compose это отдельный контейнер, а при запуске вне Compose сервер задаётся через `CLAMD_HOST` и `CLAMD_PORT`.

Для другого продукта добавьте **HTTP-шлюз локального антивируса**. Шлюз вызывает API или другой поддерживаемый интерфейс конкретного продукта и приводит ответ к формату ниже. Сам интерфейс продукта зависит от выбранного вендора. В карточке подключения задаются базовый HTTPS-адрес шлюза, имя и при необходимости Bearer-токен. Шлюз должен быть доступен из контейнера Celery worker, а сертификат должен проходить проверку TLS. Хост и тип подключения сохраняются при создании. Для переноса создайте новое подключение и отключите старое.

Контракт шлюза:

| Запрос | Данные и ответ |
|---|---|
| `POST {endpoint}/v1/scans` | Multipart с полем `file` и полем `sha256`. Ответ 200, 201 или 202 с JSON `{"id":"job-123"}`. ID до 255 символов из букв ASCII, цифр и `_+=.-`. |
| `GET {endpoint}/v1/scans/{id}` | Пока проверка идёт, верните `{"status":"queued"}` или `{"status":"in-progress"}`. После проверки верните итоговый JSON. |

```json
{
  "status": "completed",
  "sha256": "<SHA-256 проверенных байтов>",
  "verdict": "CLEAN",
  "summary": "Проверка завершена",
  "details": {"engine": "Название антивируса", "engine_version": "1.0"}
}
```

Допустимые вердикты: `CLEAN`, `SUSPICIOUS`, `MALICIOUS`, `UNKNOWN`. SHA-256 должен соответствовать содержимому, которое проверил шлюз. При сбое верните статус `failed` или подходящий HTTP-код. Для временного ограничения частоты используйте HTTP 429 и `Retry-After`. Ответ должен быть JSON до 1 МиБ. Передавайте в `details` только сведения для ИБ. В качестве имени для загрузки система использует хеш с расширением файла.

## Выдача и хранение ключей

При старте проверки файла система сохраняет список назначенных антивирусов. Для выдачи требуются чистые результаты каждого из них для того же файла и ручное согласование ИБ. Ошибка, подозрительный или неизвестный результат блокируют выдачу. Worker проверяет доступность подключения перед очередной операцией. Отключение провайдера не отзывает файлы, уже переданные ему. Заявка, уже ожидавшая его результат, потребует повтора обработки. Старые отчёты ClamAV сохраняются.

Ключ вводится в поле пароля и сохраняется в БД в зашифрованном виде. При редактировании пустое поле сохраняет текущий ключ. Для удаления есть отдельная отметка. Новый файл окружения Compose содержит `ANTIVIRUS_ENCRYPTION_KEY`. На существующей установке без этой переменной используется ключ, производный от Django `SECRET_KEY`. Храните используемый ключ шифрования вместе с резервной копией настроек отдельно от БД. При его замене сохраните ключи провайдеров заново.

ИБ может получить краткие отчёты из поля `reports` карточки REST API. Подробности доступны по `GET /api/v1/security/requests/{id}/scans/{scan_id}/` с правом просмотра заявок ИБ.
